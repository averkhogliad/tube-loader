# Tubeloader

Десктоп-менеджер скачивания видео и аудио из нескольких источников. Ядро headless,
фронтенды тонкие: команды вниз, события вверх.

## Language

**Source (источник)**:
Сайт или сервис, из которого скачивается контент: Rutube, YouTube. В коде — тип `Source(SourceId,
displayName)`: часть `MediaRef`, ядро перечисляет их через `CoreFacade.availableSources`.
_Avoid_: называть «источником» плагин или его код

**SourceAdapter (адаптер источника)**:
Плагин за контрактом ядра, обслуживающий источник или их семейство через внешний
инструмент (yt-dlp). Единственная точка, где ядро касается специфики источника.
_Avoid_: Backend, Plugin, Provider, Driver, Extractor

**Core (ядро)**:
Headless-часть приложения: роутинг URL, оркестрация, нормализация прогресса и
ошибок, staging. Без зависимостей от UI-фреймворка.
_Avoid_: бэкенд, серверная часть

**Extractor (экстрактор)**:
Фаза внутри адаптера: разбор ответа источника в потоки. Только резолвит, не качает.
Нестабильная часть адаптера.
_Avoid_: использовать как имя плагина

**Adapter (конвенция)**:
Адаптером называется только адаптация внешней системы к контракту ядра.
Внутренний перевод интерфейсов — Mapper или Wrapper.

**Staging (стейджинг)**:
Промежуточная зона недокачанного: файлы живут там, пока загрузка не завершена.
Готовый файл попадает в целевой каталог атомарным перемещением.
_Avoid_: качать напрямую в целевой каталог

**Target Directory (целевой каталог)**:
Каталог, выбранный пользователем, куда финализированные файлы попадают из staging.
_Avoid_: библиотека, library

**Progress (прогресс)**:
Нормализованная мера продвижения загрузки: `Indeterminate` (прогресс неизвестен,
например при перекодировании — прелоадер) или `Determinate(current, total)`.

**SourceProgress (сырой прогресс источника)**:
Прогресс в формате источника, отдаваемый адаптером через колбек операции скачивания:
`Indeterminate`, `Absolute(processed, total)` (байты, сегменты, любой счётный шаг) или
`Fraction(ratio)` (доли, 0.0..1.0). Пересчитанная доля выполненного — `fraction()`, `null`,
когда её назвать нельзя (см. спеку ядра, `Progress`). Ядро нормализует его в `Progress`.
_Avoid_: смешивать с `Progress` — `Progress` наружу, `SourceProgress` только на границе адаптера

**DownloadStatus (статус загрузки)**:
Фаза жизненного цикла одной загрузки: ожидание, метаданные, скачивание, финализация,
завершено, отмена (включая `Cancelling`, пока идёт остановка), ошибка. Ошибка несёт класс из
набора `DownloadError` и причину — исключение, из-за которого задача упала, либо `null`, когда
исход пришёл значением. Прерывание задачи ради проверки, требующей действия пользователя
(cookies, сессия), в M1 не закладывается: появится вместе с первым реальным сценарием.
_Avoid_: смешивать со степенью готовности — это `Progress`

**DownloadState (состояние загрузки)**:
Набор независимых измерений одной загрузки: `taskId`, `status` (фаза жизненного цикла),
`progress` (сколько выполнено), `startedAt` (момент постановки), `finishedAt` (момент
терминального статуса). Прогресс сохраняется между сменами статуса; пока задача не терминальна,
поздний колбек адаптера обновляет прогресс, но не меняет статус, а после терминального статуса
колбек игнорируется целиком.
_Avoid_: хранить прогресс внутри конкретного статуса

**Download Queue (очередь загрузок)**:
Единая очередь постановок: сверх лимита параллельных задач ждут, при освобождении слота
стартует старейшая (FIFO). Владеет только исполнением: принимает лямблу, стартует корутину,
выдаёт слот по лимиту. Жизненный цикл задачи (статусы, идентификатор) принадлежит фасаду.
_Avoid_: scheduler, планировщик, worker pool

**MediaItem (медиаэлемент)**:
Бизнес-сущность источника: то, что пользователь выбирает и скачивает. Имеет `mediaId`,
заголовок, автора, длительность, обложку, набор `Quality`. Источник-агностична: покрывает и видео,
и (в M2) только-аудио.
_Avoid_: Video, Content, Asset, Publication

**MediaRef (ссылка на медиаэлемент)**:
Указатель на медиаэлемент у конкретного источника: `source` плюс `mediaId`. Результат разбора URL
или выбора источника; вход для загрузки метаданных и постановки загрузки. URL в ссылке не хранится.
_Avoid_: таскать URL по контракту ядра, смешивать с `MediaMeta`, VideoRef

**MediaMeta (метаданные медиаэлемента)**:
Данные о `MediaItem` от источника: идентификатор, заголовок, автор, длительность, обложка,
доступные качества. Результат операции загрузки метаданных по идентификатору.
_Avoid_: VideoMeta, VideoDetails (прототип), смешивать с дорожками

**Track (дорожка)**:
Элементарный поток медиа: видеодорожка или аудиодорожка. То, что `MediaTool.mux` собирает в один
файл. Вид дорожки — перечисление `TrackKind`: `Video` / `Audio`.
_Avoid_: Stream, Format, Video, Media; называть дорожкой единицу контента

**DownloadHandle (хэндл загрузки)**:
Выданный фасадом объект одной поставленной загрузки: `taskId`, `state: Flow<DownloadState>` и
`cancel()`. Состояние задачи наблюдается через флоу хэндла; отмена — операция над хэндлом, а не
над фасадом. Список загрузок для пользователя собирает слой презентации.
_Avoid_: возвращать карту состояний наружу, адресовать отмену по `taskId` через фасад

**Find (разбор URL, `ParseUrl`)**:
Операция контракта `SourceAdapter`: извлекает `mediaId` медиаэлемента из URL и определяет,
принадлежит ли URL источнику. Исход `FindResult`: `Found(mediaId)` / `Unsupported` / `NotFound`.

**MediaFile (медиафайл)**:
Артефакт на диске — результат финализации. То, что переезжает из staging в целевой каталог;
вход/выход операций порта `MediaTool`. В коде — `Path`, термин фиксирует понятие, а не тип.
_Avoid_: VideoFile, называть дорожкой

**Quality (качество)**:
Один из доступных вариантов дорожек (видеодорожка, аудиодорожка или пара) для загрузки,
выбирается пользователем. В M1 используется только качество видео. Скачивание только аудио отложено
на M2; модель вида сохранена, чтобы M2 не ломал контракт.

**MediaTool (порт медиаинструмента)**:
Порт ядра для операций над медиафайлами: явные операции `mux` (две дорожки в один файл) и `remux`
(перезапись контейнера без перекодирования), прогресс колбеком. Сигнатура `mux`: параметры
`videoTrack`, `audioTrack` — единицы дорожек. Что вызвать, знает адаптер;
реализация порта транслирует вызов во встроенную библиотеку или в аргументы CLI-процесса, так что
инструмент можно заменить без правок адаптеров. Готовности инструмента в контракте нет: реализация
инициализируется лениво, сбой виден как `Result.failure` операции. Отмена корутины, в которой идёт
операция, прерывает её: реализация порта гасит дерево процессов запущенного инструмента целиком,
осиротевших дочерних процессов не остаётся.
_Avoid_: запускать внешний инструмент в обход порта

**HttpTool (порт HTTP-чтения)**:
Порт ядра для чтения по HTTP. Адаптер не выбирает клиентскую библиотеку: он просит порт открыть
ресурс по URL и заголовкам и копирует тело сам. Плейлисты и сегменты разбирает и качает адаптер.
`HttpTool.open` возвращает `Result<HttpResponse>`: `Result.failure` — для транспортных сбоев,
`Result.success` — для всего, что сервер ответил, включая 4xx/5xx.
_Avoid_: тянуть HTTP-клиент прямо в адаптер

**HttpResponse (ответ порта HTTP-чтения)**:
Интерфейс значения, которое отдаёт `HttpTool.open`. Несёт `status: Int` и `contentLength: Long?`;
body читается двумя формами — `content(): InputStream` (закрывает вызывающий) и
`content(block)` (закрывает порт). Обе формы отдают уже распакованный поток: реализация порта
снимает `Content-Encoding` до возврата. Headers ответа входят в контракт (`headers`, поиск по имени
без учёта регистра); `Content-Type`, редиректы и подтипы ответа сознательно вне контракта
(ADR-0005).
_Avoid_: `data class` с `val body: InputStream` — закрытие стрима съезжает на каждый адаптер

**Transport error vs application error (различение в порту)**:
`Result.failure` из `HttpTool.open` — транспортный сбой (DNS/TCP/TLS/timeout/EOF). `Result.success`
со `status != 2xx` — сервер ответил приложению отказом (404/403/503). Retry-движок опирается на
эту границу в `judging`: первое ретраится, второе — нет (если статус не в
`HttpToolConfig.retriableStatuses`).
_Avoid_: смешивать два класса отказа в один исход

**Content-Encoding декодирование (ответственность порта)**:
Реализация `HttpTool` снимает `gzip`/`deflate` до возврата body адаптеру; адаптер получает
распакованный поток. По дефолту `Accept-Encoding: identity` — сервер не сжимает body и
декодирование не нужно; адаптер может явно переопределить заголовок (`Accept-Encoding: gzip`),
порт всё равно отдаст распакованный поток.
_Avoid_: декодировать `Content-Encoding` в адаптере
