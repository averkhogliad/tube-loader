# 0013: Логирование — фасад slf4j-api, backend logback-classic

## Status

Принято. Применяется с M1 (тикет #137).

## Context

Единственный логирующий код сегодня — `FfmpegMediaTool` (`:infra`): три диагностических сообщения
через `System.err.println` (недоступность инструмента, командная строка, провал операции).
Композиция smoke перехватывает stderr целиком (`System.setErr` + `LineSinkStream`), чтобы вернуть
строки на дашборд — трюк ради отсутствия шва. Ручной префикс вместо имени логгера, уровней нет,
приёмник не сменить без правки модуля.

Ядро не логирует: его диагностика едет значениями (`Progress`, `DownloadState`, причина отказа —
фича failure-reason, #135). Логирование — забота слоёв реализации и композиции. В
`gradle/libs.versions.toml` лог-зависимостей нет.

Впереди фронтенды: Compose Desktop GUI (M1), mosaic TUI (M2) — у каждого свой backend (консоль
smoke, файл GUI). Выбор стека — решение этого ADR.

## Decision

Фасад `slf4j-api` в логирующих модулях; backend — зависимость композиции/фронтенда, модулями не
выбирается. Первый backend — `logback-classic` в `:tools:smoke` (console); GUI подставит свой
(rolling file) в своей фиче.

Kotlin-эргономика — property-делегат `val logger by slf4j()` по образцу существующих делегатов
(имя логгера по классу инстанса, перегрузки по имени/KClass), живёт в `:infra` — единственном
логирующем модуле M1; переезд в общий пакет — с первым логирующим потребителем вне `:infra`.
Обёртки (kotlin-logging) не заводятся.

Границы: `:core` не логирует (headless, диагностика — значениями); `:infra` логирует;
`:adapters` — через тот же фасад, когда появятся сообщения. Диагностические записи в
`System.out`/`System.err` из модулей запрещены (пользовательский вывод CLI — не лог).

## Considered Options

- **logback-classic (выбран).** Референсная реализация slf4j, пара без binding-слоя; два jar,
  ~800 КБ; программный конфиг и кастомный аппендер (`AppenderBase`) — дешёвые, это сценарий
  smoke; rolling file для GUI из коробки.
- **log4j2.** Отвергнут для desktop: козыри — серверные (async loggers на LMAX Disruptor,
  JSON-энкоды, structured logging, routing-фильтры); требует binding `log4j-slf2j-impl` и тащит
  поверхность (lookups), которую desktop не использует. Вернуться при появлении серверного
  получателя (ELK/структурированный пайплайн).
- **slf4j-simple.** Отвергнут: нет аппендеров и рантайм-настройки — сценарий «свой аппендер для
  smoke» невозможен.
- **kotlin-logging.** Отвергнут: делегат даёт ту же эргономику без зависимости; пересмотр при
  больше пяти логирующих местах.
- **JUL.** Отвергнут: неудобный API, слабая экосистема аппендеров.
- **Seam-колбек `log: (String) -> Unit` параметром.** Отвергнут: переизобретает маршрутизацию,
  уровни и файловые логи; смена приёмника — правка каждого потребителя.

## Consequences

**Положительные.**
- Один фасад на все модули; смена backend'а — смена зависимости композиции, модули не трогаются.
- Смерть `System.setErr`-перехвата и `LineSinkStream` в smoke; уровни и имена логгеров вместо
  ручного префикса.

**Отрицательные.**
- Две зависимости ради одного логирующего класса M1 — осознанная предоплата под фронтенды.
- Конфиг backend'а — новая забота каждого композиционного корня.
