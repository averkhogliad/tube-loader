# Ошибки: как их передавать

Источник истины по передаче ошибок между швами. Форма выбирается при проектировании шва, до
написания кода.

## Категории

| Категория | Форма |
|---|---|
| Бизнесовая ошибка — ожидаемый исход операции | значение метода |
| Инвариант поведения или состояния системы | sealed-класс |
| Общий случай без бизнес-состояний | `Result` |
| Паника — внештатная ситуация, необрабатываемая на месте | исключение |

## Разбор

**Бизнесовая ошибка.** Ожидаемый исход, который вызывающий обязан разобрать: «не найдено»,
«временная сеть», «протух URL», «поломка экстрактора». Возвращается значением — вызывающий
разбирает исход, а не ловит исключение. Форма: sealed-тип исхода операции — `ResolveResult`
(`Resolved(MediaRef)` / `Unsupported` / `NotFound`), `FindResult`
(`Found` / `Unsupported` / `NotFound`), `LoadMetaResult` (`Found` / `NotFound`),
`DownloadResult` (`Success` / `Failed(error)`).

**Инвариант поведения или состояния.** Конечный набор состояний, каждому из которых
соответствует своя реакция: `DownloadStatus` (жизненный цикл задачи).

**Общий случай без бизнес-состояний.** Различать нечего, кроме «получилось / не получилось»,
причину шов не классифицирует: операция порта возвращает `Result<Unit>` (так у `mux`/`remux`); порт,
отдающий значение, возвращает его напрямую, например `HttpTool.open(url, headers): HttpBody`.

**Паника.** Внештатная ситуация, которую нельзя обработать на месте: невалидный конфиг на
входе, невалидный аргумент. Здесь исключение — правильный канал. На границе ядра паника не
глушится и не превращается в бизнес-ошибку: фоновая задача переходит в терминальное состояние
с классом из набора, а не остаётся в промежуточном.

**Отмена — не ошибка.** Отдельный терминальный исход, а не класс набора ошибок.

## Проверка

Шов, отдающий исход, покрывается тестом на каждый исход и на каждый класс набора. Класс ошибки
различим в наблюдаемом состоянии, а не только в логе.

## Где применяется

Канонические примеры — контракт `SourceAdapter` (`core/.../SourceAdapter.kt`) и порт `MediaTool`
(`core/.../MediaTool.kt`); классификация ошибок задачи — `DownloadError` и `DownloadResult`
рядом с ними. Роль порта в стеке — `docs/tech-stack.md`.

Новый шов с ошибками проектируется по таблице категорий; отклонение фиксируется в спеке фичи
или в ADR.
