# Smoke-инструмент: headless-прогон пайплайна

## Problem Statement

Ядро реализовано, но прогнать его end-to-end нечем: единственный вход — тесты с фейками, живой
запуск не имеет точки входа, приложения ещё нет, а фронтенд отложен до M2. Разработчик не может
посмотреть, как скачивание идёт вживую (реальный HTTP, реальный ffmpeg, реальный yt-dlp), и не
может проверить вход по идентификатору медиаэлемента: у ядра он есть, а у инструмента — нет.

## Solution

`tools/smoke` — CLI-инструмент, который собирает граф ядра вручную и прогоняет реальный пайплайн:
разрешение → метаданные → постановка → наблюдение → отмена. Инструмент адресует медиаэлемент
двумя способами — парой `-url <url> -name <name>` и парой `-id <code>:<mediaId> -name <name>`.
Вторая — проверка входа по ID ядра тем же путём, каким пойдёт фронтенд.

График и состав источников инструмент собирает сам: это проверка, что куски сходятся, а не
сборка приложения. Граф зависимостей приложения — отдельная задача (фаза DI).

## User Stories

1. Как разработчик, я хочу указать URL и увидеть живой прогресс скачивания, чтобы проверить
   пайплайн целиком, а не по тестам.
2. Как разработчик, я хочу адресовать видео кодом источника и идентификатором, чтобы проверить
   вход по ID и не искать URL.
3. Как разработчик, я хочу, чтобы неизвестный код источника останавливал прогон с понятным
   сообщением и списком известных кодов, чтобы опечатка не выглядела как «видео не найдено».
4. Как разработчик, я хочу отменить загрузки по таймеру, чтобы проверить ветку отмены.
5. Как разработчик, я хочу, чтобы смоук не собирал продакшн-граф зависимостей, чтобы диаграмма
   приложения оставалась отдельной задачей.
6. Как разработчик, я хочу, чтобы недоступный ffmpeg назывался в прогоне, чтобы сбой был виден
   как «нет инструмента», а не как «источник сломался»; yt-dlp при этом качается сам (ADR-0012).

## Implementation Decisions

**Адресация цели.** Два вида целей, обе — пары именованных аргументов одинаковой фиксированной
арности:

- `-url <url> -name <name>` — URL целиком; источник определяет ядро.
- `-id <code>:<mediaId> -name <name>` — код источника и идентификатор медиаэлемента.

Обе формы — один и тот же способ адресации: URL передаёт тот же идентификатор, только извлечённый
из ссылки, поэтому и правила у форм одни. `-name` обязателен и стоит сразу после своей цели,
между ними ничего нет; пары повторяются — несколько пар, несколько целей. Фиксированная арность
гарантирует, что по команде всегда видно, к какой цели какое имя относится.

Позиционных аргументов у команды нет: всё, что не флаг — ошибка команды с usage-текстом, а не
угаданная цель. Разделитель в `-id` — первое двоеточие. Код источника приводится к нижнему
регистру, идентификатор остаётся как есть: регистр в идентификаторе значим. Голый идентификатор
без кода — ошибка команды: источник по идентификатору не угадывается, у разных источников
идентификаторы одного вида.

**Проверка кода — после сборки графа.** Список кодов известен только после сборки: его отдаёт
`CoreFacade.availableSources`. Поэтому коды целей проверяются после сборки графа и до старта
загрузок: неизвестный код — ошибка команды со списком известных кодов, ни одна загрузка не
начинается. Дублировать реестр источников внутри смоука нельзя: тогда список кодов разъедется с
настоящими источниками.

**Имя файла.** Имя целиком задаёт команда: обязательный `-name` при каждой цели. Автоимени по
идентификатору медиаэлемента нет — плавающая арность пары мешала бы понять, к какой цели какое
имя относится. Имя санируется: запрещённые в имени файла символы заменяются, пустое имя — `video`.

**Инструменты на машине.** Оба инструмента готовятся при инициализации прогона, до разрешения целей:
ffmpeg — `ensureManagedFfmpeg`, yt-dlp — `ensureManagedYtDlp` (та же дистрибуция ADR-0012, ensure
идемпотентен). Цель ждёт источник, а не сеть: скачивание инструмента не попадает ни в `resolving`,
ни в загрузку. yt-dlp на машине не ищется — адаптер сам скачивает официальный бинарник при первом
обращении (ADR-0012) и запускает его по абсолютному пути; сбой виден как отказ источника, а не как
«нет инструмента на машине». ffmpeg нужен обеим веткам: делегирующий адаптер передаёт путь к нему
инструменту, который стартует раньше, чем до `MediaTool` дойдёт первый вызов, поэтому бинарник
обязан быть на диске до старта загрузки. Недоступный инструмент — не сбой прогона: заметка уровня
прогона, а цель пропускается с указанием причины (ffmpeg) или падает отказом источника (yt-dlp).

**Отмена.** `-cancel-after <s>` — отменить все идущие загрузки через `s` секунд после старта
первой. Отмена идёт через use-case отмены, а не убийством процесса из инструмента.

**Прогресс.** Живая таблица: строка на каждую цель команды с самого старта — выровненное имя,
рядом статус и прогресс; таблица перерисовывается на месте. Статусы: `planned` → `resolving` →
`queued` / `loading metadata` / `downloading N%` / `downloading -` / `finalizing` / `cancelling`
→ `done (файл, 12s)` / `cancelled` / `failed: <класс ошибки>[: <причина>]` / `skipped: <причина>`. Терминальный
исход остаётся в строке своей цели, а не печатается отдельной строкой: таблица — это и есть отчёт
прогона. По завершении прогона таблица остаётся на экране. Заметки уровня прогона (сбой внешнего
инструмента, мусор stderr) печатаются постоянными строками над таблицей. Отдельный файл прогресса
не ведётся.

**Конфигурация.** Дефолты — из classpath-конфигурации инструмента, поверх — файл рядом с
рабочим каталогом (`config/config.toml`, `config.toml`) и `<out>/.tubeloader/config.toml`.
Переопределения: каталог результата, число параллельных загрузок, формат контейнера, параметры
yt-dlp.

## Testing Decisions

**Шов — разбор аргументов.** Разбор командной строки проверяется тестом: адрес цели (`-url`,
`-id`), разделитель кода и идентификатора, обязательность `-name` у обеих форм и соседство имени
со своей целью, приведение кода к нижнему регистру, ошибки на мусорном входе — неизвестный
аргумент, значение не-URL у `-url`. Ошибка несёт usage-текст.

**Шов — разрешение кода источника.** Проверка кодов — на настоящем `CoreFacade`: известный код
находит источник, неизвестный даёт ошибку со списком кодов. Реестр источников в тесте не
дублируется — берётся тот же список, что и в смоуке.

**Шов — имя цели.** Имя файла проверяется на каждой стадии: имя из команды, санитизация.

**Шов — таблица прогресса.** Таблица проверяется на отрисованном терминале (`Screen`): строки идут
в порядке целей команды, строка обновляется на месте через все фазы, прогресс — `N%` или `-`,
терминальный исход остаётся в своей строке, скип цели называет причину в своей строке, `close`
оставляет таблицу на экране как отчёт, перенос длинной строки не оставляет хвостов.

**Без сети.** Живой прогон (yt-dlp, ffmpeg, HTTP) — вне `check`: он требует реальных инструментов
и сети. Contract-тесты адаптеров и тесты ядра — обычные тесты.

## Out of Scope

- Граф зависимостей приложения (фаза DI): смоук собирает граф ядра руками и не претендует на
  продакшн-сборку.
- Фронтенды (Compose Desktop, TUI): слой представления — отдельные спеки.
- Автоматические прогоны в CI: живые инструменты в CI не заведены.
- Плейлисты, каналы, субтитры, главы: вне M1.
